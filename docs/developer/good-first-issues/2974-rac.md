## The method, briefly

Layer-wise compression solves `min || W X − Ŵ X ||²`, where `X` is the
calibration activation matrix. Conventional calibration fills `X` from prompt
text, which suits workloads where `|prompt| >> |completion|`.

Reasoning models invert that: they emit thousands of chain-of-thought tokens per
query, so `|decode| >> |prompt|`. Calibrating on prompts (or C4) optimizes for a
distribution the model barely occupies at inference.

RAC concatenates decode-phase activations from the model's own rollouts:

```
X_l^RAC = [ X_l^prompt   X_l^decode ]      # plain concatenation, no reweighting
```

**The key simplification:** because it is an unweighted concatenation, a
teacher-forced forward pass over the string `prompt + generated_CoT + answer`
produces the same activation matrix. So RAC needs no algorithmic change at all —
generate traces once, then feed `prompt + trace` to the existing path. This is
why it reduces to a data-preparation script, and why the maintainers were right
that no modifier changes are required.

The paper's headline (DeepSeek-R1-Distill-Qwen-7B, SparseGPT 50%, MATH-500):

| Calibration set | Accuracy | Eval runtime |
|---|---|---|
| C4 | 0.744 | 135.0 min |
| Task prompts only | 0.812 | 115.6 min |
| **RAC** | **0.900** | **35.3 min** |

Note the runtime column: the C4-calibrated model is both *worse* and ~4× slower
to evaluate, because a badly calibrated reasoning model rambles. "Compression
made my model slower" is the symptom users will actually search for.

## The replication result — read this before promising a win

`AbigaleD` ran the comparison at single-GPU scale and **did not reproduce the
on-policy advantage**. Two experiments, both token-budget matched:

**Qwen3-1.7B → W4A16 AWQ, mmlu_cot_llama (1140 questions):**

| Calibration data | Loss-mask tokens | Accuracy |
|---|---|---|
| BF16 reference | – | 0.597 |
| Plain AWQ, no mask | – | 0.559 |
| Dataset responses, masked | 408k | 0.604 |
| Own CoT, masked | 408k | 0.610 |

**Qwen3-1.7B → AWQ, minerva_math500 (500 problems, ~510k tokens each):**

| Calibration data | W4A16 | W3A16 |
|---|---|---|
| BF16 reference | 0.812 | – |
| Plain AWQ, no mask | 0.736 | 0.048 |
| Dataset responses, masked | **0.778** | 0.084 |
| Own CoT, masked (RAC) | 0.752 | 0.054 |

Paired McNemar tests at W4A16:

- masked dataset responses vs plain AWQ: **p = 0.009** — masking the prompt helps
- own CoT vs dataset responses: **p = 0.12**, slightly favouring *dataset
  responses*

Her conclusion:

> At an equal number of loss tokens, on-policy traces and dataset responses are
> within noise of each other. The gain I originally saw for on-policy was mostly
> the larger number of calibration tokens that long CoT traces provide.

**What this means for the plan.** The robust, reproduced effect is **prompt
masking**, not on-policy generation. Two consequences:

1. Frame the example around masked long-form calibration data, and present
   on-policy traces as the paper's method under evaluation — not as a guaranteed
   improvement.
2. **Control for token budget.** The original apparent win came from CoT traces
   simply being longer. Any comparison that does not equalize loss-mask tokens
   measures dataset size, not methodology.

The author (`PKUWZP`) disputes the framing, maintaining RAC is an end-to-end
method rather than data preparation, and that the paper targets sparsity at
higher ratios. Both can be true: the scoping stands for this issue, and the
sparsity regime is untested here. `HDCharles` offered compute:

> if you have a set of experiments that you lack the compute to run, if you set
> them up in a PR I can run them

Making the scripts trivially re-runnable (`MODEL=...`) is therefore part of the
deliverable, not a nicety.
